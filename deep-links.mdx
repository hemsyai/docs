## Overview

**Deep links** are URLs that configure how Hemsy opens: a pre-loaded product, a
flow's starter look, or a shared look, plus optional attribution IDs. Use them
from product pages, emails, ads, blog posts, or collection tiles so customers
don't have to build a look from scratch or lose tracking context.

Hemsy supports these query parameters for pre-populating or attributing a
session:

| Param            | Purpose                                                                                  |
| ---------------- | ---------------------------------------------------------------------------------------- |
| `?product=`      | Shortcut for a **single product** by Shopify ID or handle.                               |
| `?share=`        | A **shared look** short ID, used by the in-app Share feature.                            |
| `?flow=`         | Opens a **flow** on its starter look, by flow ID (copy it from the dashboard's Flows page). With `?product=`, opens that product in its flow step. |
| `?anonymous_id=` | Anonymous visitor ID passed into Hemsy for analytics, attribution, and integrations.     |

All of these can be combined with `?store=<slug>` on [staging](/staging) and
preview deployments to target a specific tenant.

<Note>
  Include `anonymous_id` whenever the storefront has an anonymous visitor ID
  available. Today, Hemsy uses it for Twilio Segment tracking and checkout/order
  attribution. Longer term, it should be treated as the shared anonymous
  identity for all integrations that need to connect Hemsy activity back to
  storefront activity.
</Note>

## `anonymous_id`: Visitor attribution

`anonymous_id` is an optional query parameter that lets the merchant storefront
tell Hemsy which anonymous visitor is opening the experience.

Use it when launching Hemsy from:

- Embedded storefront buttons
- Product page links
- Email or ad links where the visitor ID is available
- Any integration that wants to reconcile Hemsy events with storefront behavior

Example:

```txt
https://yourstore.hemsy.ai/?anonymous_id=visitor-42
```

Combined with a product shortcut:

```txt
https://yourstore.hemsy.ai/?product=organic-cotton-duvet&anonymous_id=visitor-42
```

Combined with a shared look:

```txt
https://yourstore.hemsy.ai/?share=abc123&anonymous_id=visitor-42
```

### What `anonymous_id` does

When present, Hemsy uses `anonymous_id` to:

- Attach the visitor identity to Hemsy analytics events.
- Pass the same identity through checkout creation, so it can surface on the
  Shopify order as an additional detail/custom attribute when the order is
  placed through Hemsy checkout.
- Provide a stable identity key for supported integrations.

<Note>
  Current integration support is focused on Twilio Segment. Merchants should
  still pass `anonymous_id` consistently now so Hemsy can use the same identity
  for additional integrations as they are added.
</Note>

<Warning>
  If a shopper visits a Hemsy-hosted URL directly, for example by typing
  `https://yourstore.hemsy.ai/` into the browser, Hemsy cannot infer the
  anonymous visitor ID from the merchant's storefront domain. The storefront
  must pass the ID explicitly via `anonymous_id` in the URL or via the embed
  script configuration.
</Warning>

## `?product=`: Single-product shortcut

For the common case of "launch Hemsy with one product pre-loaded", `?product=`
accepts either:

- A numeric Shopify **product ID**: `?product=8888888888888`
- A Shopify **GID**: `?product=gid://shopify/Product/8888888888888`
- A product **handle**: `?product=organic-cotton-duvet`

```txt
https://yourstore.hemsy.ai/?product=organic-cotton-duvet
```

With visitor attribution:

```txt
https://yourstore.hemsy.ai/?product=organic-cotton-duvet&anonymous_id=visitor-42
```

The product is added as the first layer and rendered on your first model photo
right away.

---

## `?share=`: Shared-look links

`?share=<shortId>` is reserved for links generated by Hemsy's in-app Share
feature. The short ID resolves server-side to a previously saved look: user
photo, generated image, and full selection. You don't need to construct these
yourself. They're produced by the app when a shopper taps **Share**.

If the storefront knows the visitor identity, append `anonymous_id` to shared
look links too:

```txt
https://yourstore.hemsy.ai/?share=abc123&anonymous_id=visitor-42
```

---

## `?flow=`: Flow links

`?flow=<flowId>` opens a flow on its starter look: one layer per flow step,
already filled in with the merchant's starter picks, and the saved starter
render. See [Launch Modes](/embeds/launch-modes#flow) for how flows are set up.

```txt
https://yourstore.hemsy.ai/?flow=YOUR_FLOW_ID&anonymous_id=visitor-42
```

Combined with `?product=`, the flow opens with that product in its matching
step, the other steps empty, and the product rendered right away. See
[Product context in a flow](/embeds/launch-modes#product-context-in-a-flow).

```txt
https://yourstore.hemsy.ai/?product=organic-cotton-sheet-set&flow=YOUR_FLOW_ID
```

`?flow=` is ignored when the link also carries `?share=`.
